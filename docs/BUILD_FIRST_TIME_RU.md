# Первая сборка Gwent Beta Classic 0.9.0 с нуля

Инструкция сверена с `CleanBuild/build.py`, `pack.py`, `maintenance.py` и
командными файлами комплекта 19 октября 2026 года. Она описывает новый запуск
на Windows без прежних результатов компиляции.

## 1. Получить полный комплект исходников и ресурсов

Для первого запуска нужен **весь автономный комплект `CleanBuild`**, а также
установленные инструменты и Classic 1.32. Обычный `git clone` публичного
репозитория не содержит графику, звук, шаблоны нативных меню и автономные
зависимости. Два игровых ZIP также не заменяют комплект сборки.

В рабочем проекте комплект находится в `D:\w3mod\CleanBuild`. Уже подготовленный
архив для переноса:
`D:\w3mod\GwentBeta-CleanBuild-20261018T211849Z-bd8cc4ef.zip`.
Рядом лежит одноимённый файл `.zip.sha256`. Эти файлы локальные; данная
инструкция не означает, что архив загружен на GitHub или Nexus. Для другого
ПК отдельно передайте комплект и контрольную сумму.

Проверьте SHA-256 архива командой `Get-FileHash -Algorithm SHA256` и сравните
значение с `.sha256`. Распакуйте комплект, например в `D:\GwentBuild`.
Ниже эта папка — каталог, **в котором непосредственно лежат** `Build.cmd`,
`build.py` и `config.example.json`. Если распаковщик создал вложенный
`CleanBuild`, перейдите в него.

В полном комплекте должны присутствовать:

| Путь | Содержимое |
| --- | --- |
| `source/scripts` | Редактируемые WitcherScript |
| `BetaGwent/ui/src` | Интерфейс Next-Gen |
| `source/classic-ui/src` | Интерфейс Classic |
| `BetaGwent/native/clipboard` | C++ исходники моста буфера обмена и теста |
| `BetaGwent/ui/assets` | Графика и атласы |
| `inputs` и `asset-manifest.json` | Подготовленные ресурсы, звук, шаблоны и их хэши |
| `tools/vendor` | Закреплённые Python-зависимости и Apache Royale |
| `documentation` | Документы, которые упаковщик кладёт в игровые архивы |

**Ревизия имеет значение.** Имеющийся переносимый экспорт подготовлен на основе
`release090-final5`; это отмечено в `inputs/provenance.json` и экспортёре
`tools/export_clean_build.py` родительского проекта. Он не является точной
копией более поздних final9/final11. В частности, позднее менялось
восстановление профиля. Для воспроизведения конкретного нового выпуска сначала
нужен комплект с согласованными исходниками обеих платформ и ресурсами именно
этого выпуска. Одно переименование ZIP не обновляет код.

## 2. Установить внешние инструменты

Нужны Windows x64 и следующие компоненты:

| Компонент | Что требуется сборщику |
| --- | --- |
| CPython **3.13 x64** | Именно эта версия и архитектура: встроенные расширения привязаны к её ABI. Удобно установить Python Launcher `py`. |
| Java 11 | Путь к настоящему `bin/java.exe`. |
| Visual Studio 2022 / Build Tools | C++ x64, компилятор MSVC, стандартная библиотека C++ и Windows SDK. |
| The Witcher 3 **Classic GOG 1.32** | Оригинальный EXE, штатные ресурсы и исходные скрипты `content/content0/scripts`. |
| The Witcher 3 REDkit | `wcc_lite.exe`, GFx exporter, исходники `r4data/scripts` и ActionScript API. Условия SDK должны быть приняты пользователем до сборки. |

Подготовьте REDkit штатным способом до появления следующих файлов и каталогов:

```text
<REDkit>/bin/x64_RedKit/wcc_lite.exe
<REDkit>/bin/tools/GFx4/gfxexport_mult4fix.exe
<REDkit>/r4data/scripts/
<REDkit>/r4data/gameplay/gui_new/actionscript/scaleform/gfx/KeyboardEventEx.as
```

Одного установленного лаунчера REDkit без исходников SDK недостаточно. Если
скриптов или API нет, завершите подготовку данных REDkit; пустые папки их не
заменяют.

Поддерживаемый SHA-256 `Classic/bin/x64/witcher3.exe`:

```text
5112253787fbd927ecb979207efb91b99bcc9c7b041106b51285136bab41e1f7
```

Другой EXE отклоняется: адаптер результата компиляции проверен для этой версии.
Classic нужен даже для `--platform nextgen`, поскольку из его штатных скриптов
готовятся совместимые интерфейсные связи. Установленная Next-Gen для сборки
не обязательна: её скрипты компилирует REDkit.

Wwise и исходный клиент беты для этого пути не нужны: комплект использует
подготовленные BNK/WEM, изображения и графические шаблоны. Он заново собирает
код, баннеры и игровые контейнеры, но не извлекает все ассеты из сырых клиентов.
Не запускайте старые генераторы звука и ресурсов вместо этого конвейера.

Оставьте не менее 30 ГБ свободного места для комплекта и одной полной сборки.
Следующие запуски сохраняют свои результаты и требуют дополнительного места.

## 3. Настроить пути

Откройте PowerShell в папке комплекта:

```powershell
Set-Location 'D:\GwentBuild'
py -3.13 -c "import sys, struct; print(sys.version); print(struct.calcsize('P') * 8)"
Copy-Item -LiteralPath '.\config.example.json' -Destination '.\config.local.json'
notepad.exe '.\config.local.json'
```

Команда Python должна показать 3.13 и 64. Копируйте конфиг один раз, при первом
запуске; при дальнейших сборках сохраняйте свои настройки.

В JSON укажите реальные пути своей установки. Пример структуры:

```json
{
  "classic_game": "C:/Games/The Witcher 3 Classic",
  "redkit": "C:/Games/The Witcher 3 REDkit",
  "java": "C:/Program Files/Microsoft/jdk-11/bin/java.exe",
  "msvc": "C:/Program Files/Microsoft Visual Studio/2022/BuildTools/VC/Tools/MSVC/14.xx.xxxxx",
  "windows_sdk": "C:/Program Files (x86)/Windows Kits/10",
  "windows_sdk_version": "10.0.xxxxx.0",
  "nextgen_executable": ""
}
```

Замените `14.xx.xxxxx` и `10.0.xxxxx.0` на установленные версии. `msvc` указывает
на каталог версии, внутри которого есть `bin/Hostx64/x64/cl.exe` и `include/vector`.
`windows_sdk_version` — имя версии внутри `Windows Kits/10/Lib`; в ней нужны
`um/x64/user32.lib` и `ucrt/x64/libucrt.lib`. Пути с пробелами поддерживаются;
в JSON удобно использовать `/`, как в примере.

`nextgen_executable` можно оставить пустым. Полный путь к своему Next-Gen EXE
добавляет проверку его распознавания нативным модулем.

Если команды `py` нет, перед следующими командами задайте интерпретатор:

```powershell
$env:CLEAN_BUILD_PYTHON = 'C:\Path\To\Python313\python.exe'
```

Это должен быть CPython 3.13 x64. Отдельные `pip install` не нужны: сборщик
использует зависимости из `tools/vendor`, без загрузок из сети.

## 4. Проверить комплект и собрать обе платформы

Сначала выполните проверку без компиляции:

```powershell
.\Check.cmd
```

Продолжайте после строки `PASS: environment and all prepared inputs` и нулевого
кода завершения. Проверяются инструменты, штатные скрипты, EXE, кодировка поля
и SHA-256 закреплённых ресурсов. При ошибке исправьте указанный путь либо
восстановите отсутствующий файл из полного комплекта.

Полная сборка Classic и Next-Gen:

```powershell
.\Build.cmd
```

Только одна платформа, если это требуется:

```powershell
.\Build.cmd --platform classic
.\Build.cmd --platform nextgen
```

Эти две команды — альтернативы полному запуску. Каждый вызов создаёт новую
сборку. Вариант Next-Gen также требует Classic, MSVC и остальных компонентов.

Сборщик заново подготавливает WitcherScript, компилирует скрипты выбранных
платформ, DLL/ASI и по четыре меню на платформу, проверяет нативный мост,
создаёт 18 баннеров, bundle/metadata/dependency/audio cache и игровые ZIP.
Старые результаты не подхватываются. Исходники `BetaGwentBoard.as` сохраняют
UTF-8 BOM и CRLF; пять рабочих копий интерфейса создаются автоматически.
Лимиты меню в этом конвейере: Classic 32 МиБ, Next-Gen меньше 63 МиБ.

## 5. Найти результат и убедиться в успехе

Последняя строка `SUCCESS: ...` показывает новый каталог:

```text
BetaGwent/build/<ID>/
```

В нём должны находиться `SUCCESS.json` и, для полной сборки, оба архива:

```text
archives/GwentBetaClassic-0.9.0-1.32-AllLanguages.zip
archives/GwentBetaClassic-0.9.0-1.32-AllLanguages.zip.sha256
archives/GwentBetaClassic-0.9.0-5.0+-AllLanguages.zip
archives/GwentBetaClassic-0.9.0-5.0+-AllLanguages.zip.sha256
```

Сборщик перечитывает ZIP, проверяет CRC и хэши упакованных файлов. Точные
исходники запуска записаны в `source-manifest.json`, окружение — в
`environment.json`. В `SUCCESS.json` перечислены пути архивов и их SHA-256.

При ошибке после создания каталога запуска там остаются `FAILED.json` и
`logs`. Если сбой произошёл ещё при проверке окружения, нового каталога может
не быть: текст ошибки будет в терминале. После исправления запустите
`Build.cmd` заново; продолжения частичной сборки здесь нет. Наличие отдельного
ZIP без `SUCCESS.json` не означает успешный полный запуск.

Сборка не устанавливает мод в игру. Для проверки распакуйте подходящий архив:
папку `Mods` — в каталог игры, а для Classic также `DLC`.
`Optional-CopyButton` устанавливается отдельно по вложенной инструкции.
Перед заменой мода сохраните резервные копии сохранений. Проверьте вход в
меню, коллекцию/редактор, партию, сохранение и повторную загрузку на каждой
нужной платформе. Автоматический успех компиляции не является игровой приёмкой.

## 6. Перенести комплект или удалить один результат

Для нового переносимого архива из **уже полного** комплекта:

```powershell
.\Export.cmd
```

ZIP и `.sha256` появятся рядом с папкой комплекта. Экспорт исключает результаты
сборок, `config.local.json` и Python-кэши; на другом ПК настройте конфиг заново.
Не запускайте `tools/export_clean_build.py` родительского проекта как первый
шаг на пустом ПК: это исторический экспортёр с зависимостями от старых сборок.

Удалить только ненужный результат можно командой `Clean.cmd <ID>`, подставив
точное имя его каталога из `BetaGwent/build`. Удаление выполняется только для
каталога с маркером владения сборщика; исходники и установленная игра сохраняются.

Прежние `Build-Mod.cmd`, `Build-0.9.0-Final*.cmd` и руководства этапов рассчитаны
на подготовленную рабочую папку с историческими входами. Для первого запуска
по этому руководству используются команды внутри полного `CleanBuild`.
