# После первого релиза: ИИ и анимации

2026-10-05. Первый релиз опубликован пользователем. Новые изменения готовим
отдельно от ZIP 0.2.0, через файлы и CLI, без управления интерфейсом.

## Текущий этап — 90

Первый проход: отделить немедленные очки от прогнозов движков, погоды,
добора и порядка комбинаций. Усиление Импера по уже открытым шпионам
входит в очки; предотвращённый будущий урон не становится текущим счётом.
Случайный призыв оценивать консервативно. Это оценка, не полная симуляция.

Анимации: масштаб/угол от исходного состояния каждого движения, мягкое
приземление, след удара, синхронизация счёта с попаданием, достаточно времени
для смерти/призыва/завещания. RU/EN подготовлены; игровые проверки впереди.

## Организация проверок

Каждая ошибка становится именованным сценарием: начальное состояние,
разрешённая информация ИИ, ожидаемое действие или несколько приемлемых
вариантов, фактический выбор, результат способности. Не требовать одну
конкретную карту, когда несколько ходов одинаково разумны.

Подготовить DEV-набор фиксированных ситуаций с seed и перечнем действий.
Снимок: поле, рука/колода самого ИИ, размеры скрытых зон игрока, сбросы,
лидеры, раунд, счёт, статусы. Скрытые карты игрока могут быть в фикстуре
для воспроизведения, но не передаются оценщику ИИ.
Отладочные состояния не создавать в основном сохранении.

Сначала автоматические проверки вычислений/инвариантов. Затем одна игровая
проверка группы исправлений. Принятые случаи входят в регрессионный набор;
повторяем затронутые случаи, а не весь проект после каждой правки.

## 1. Общий пас и цена карт

| Случай | Ожидаемое поведение |
|---|---|
| Игрок спасовал, ИИ впереди | Пас без лишней карты |
| Можно догнать одной картой | Дешёвый ответ с достаточным реальным темпом |
| Импера: сила 6, пять шпионов, отставание 10 | 16 очков, догнать одной картой |
| Нужны 2–3 карты при равных руках в первом раунде | Обычно уступить раунд |
| Большое преимущество по картам | Допустить выгодную погоню, сохранив преимущество |
| Уже потрачена карта после паса | Учитывать суммарную цену всей погони |
| Проигрыш раунда завершает матч | Отдельная политика защиты матч-пойнта |
| Ничья означает поражение в матче | Не соглашаться при доступном выигрывающем ответе |
| Лидер догоняет без расхода руки | Отдельно считать цену лидера |
| Победа в ненужном раунде опустошает руку | Сохранить карты на решающий раунд |
| Погода больше не ударит спасовавшего игрока | Не прибавлять будущие тики к счёту |
| Рассвет: очистка или случайный призыв | Прогноз соответствует выбранному варианту |
| Два удара в одну цель | Не считать уничтоженную силу дважды |
| Два призыва используют один остаток колоды | Не считать одни копии дважды |
| ИИ впереди, игроку нужно несколько ответов | Оценить безопасный пас с учётом публичных угроз |

Пройти короны 0:0, 1:0, 0:1, 1:1; разные размеры рук; пустую колоду;
доступного/использованного лидера; дешёвый ответ против финишера;
шпиона с добором; сохранённые карты будущего раунда.

Критерий: стратегические веса не прибавляются к счёту; решения объясняются
в логе; после реального разрешения ИИ пересчитывает состояние. Случайные
результаты не выдаются за гарантированные очки.

## 2. Цели, позиции и контроль

Убийство движка против простого урона; броня/щиты; блокировка и снятие
блокировки; союзные/вражеские завещания; симметричный урон и сжигание своих;
иммунитет; одинаковая максимальная сила; пустые/полные ряды; соседство;
перемещение в погоду/из неё; засады; обречённость; повреждение, временное
и постоянное усиление.

Воскрешение/призыв выбирают только доступные карты нужной зоны. Редкость
сама по себе не делает цель лучшей. Обязательный выбор завершается даже
при невыгодных вариантах. Цена контроля учитывает реакции противника.
Критерий: легальные действия, нет зависших запросов и пустых выборов.

## 3. Поиск коротких комбинаций

После общих оценок проверить несколько лучших первых действий и 1–2
следующих хода самого ИИ на независимом состоянии. Ограничить кандидатов
и глубину; отдельно учитывать случайные развилки. Сравнивать порядок,
общие цели, израсходованные копии, лимиты рядов, активации и размер руки.

Прогноз не изменяет живой матч, очередь эффектов и его RNG. Измерять время
решения; увеличивать глубину после подтверждённого улучшения качества.
Искусственно ждать 25–30 секунд не требуется.

## 4. Архетипы по очереди

| Порядок | Колода | Проверяем |
|---|---|---|
| 1 | Погода Чудовищ | Муллиган Мороза под гончих; Драккары/Всадники; Йотун/Карантир; цели Имлериха/Нитраля; Игни, Ирис, Пугач, Оззрел |
| 2 | Шпионы Нильфгаарда | Движки до шпионов; реальный Импера; добор; Иоахим; Раинфарн только из колоды; сохранение контроля |
| 3 | Полоски Севера | Подготовка усилений; порядок бойцов/разведчиков; прореживание; соседство; Фольтест |
| 4 | Скоя’таэли | Отдельно дворфы, эльфы и засады: движки, усиления, прореживание, раскрытие, контроль |
| 5 | Сброс Скеллиге | Бран/Мышовур; выгодный сброс; возвращение; воскрешение; сильный третий раунд |
| 6 | Остальные профили | Проверка семьями механик и отдельные случаи отличающихся связок |

Каждый профиль: состав → муллиган → первые ходы → комбинации → пас/погоня
→ второй/третий раунд → ответы на соперника. Спорные стратегии уточнять
у пользователя конкретным вопросом с примером поля.

## 5. Полные матчи и статистика

После локальных сценариев серии матчей на фиксированных seed, с переменой
первого игрока. Соперники: рой, контроль, движки, большой темп, шпионы,
погода, сброс; включить квестовые составы.

Измерять не только победы: лишние карты после паса, пропущенные связки,
потраченные финишеры, ошибки целей, прогноз/факт, время решения,
зависания запросов и незаконные действия. Плохие матчапы допустимы;
не назначать всем колодам целевой процент побед.
Критерий: нет обязательных ошибок правил, улучшение на тех же случаях/seed.

## Анимации: источник и порядок

Пользователь разрешил декомпилировать локальный Gwent 0.9.24. Клиент
не изменяем. Есть разбор IL 13 типов анимаций: beta-animations80-source.json
и beta-animations80-il.txt в docs/evidence. Сериализованные кривые ещё
не перенесены; IL сам по себе не является готовым эффектом.

1. Найти изображения поля, рамки, подсветки, VFX-текстуры, материалы
   и сериализованные параметры в AssetBundles; записать источник/хеши.
2. Визуальный эталон: зоны, размеры/углы карт, подъём из руки, полёт,
   приземление, момент звука и изменения силы.
3. Поле и движение карт; адаптация 3D/Unity-эффектов под GFx.
   Извлечённый Unity-шейдер не становится автоматически рабочим в REDkit UI.
4. Урон, усиление, броня, блокировка, призыв, превращение, смерть,
   обречённость, поглощение, завещание; затем погода, засады, раунды.
5. Длинные цепочки, ускорение, пропуск, сокращённые эффекты;
   мышь/контроллер, разрешения, память/FPS.

Критерий: понятны источник/цель/результат; числа и звук совпадают с ударом;
эффекты завершаются; скрытая рука/засада не раскрывается; пропуск анимации
не исполняет карточные правила повторно.

## Формат отчёта

Версия/язык; NPC/колода ИИ; своя колода; раунд/короны/счёт/размеры рук;
поле со статусами; последние действия; ход ИИ; предпочтительный ход
и причина. По возможности скриншот/видео, лог и сейв перед ситуацией.
Одна проблема — один сценарий. Проверки на резервной копии сейва.

## Следующая контрольная точка

Подготовить воспроизводимые случаи паса/реального темпа и одну сборку
для общей проверки. Затем принять Погоду; визуальные улучшения проверять
в том же проходе. Этап90 не объявлять окончательным улучшением всех
40 профилей без игровых отчётов.
