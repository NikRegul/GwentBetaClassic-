# Как устроен ИИ и где его менять

ИИ работает на стороне WitcherScript. ActionScript только показывает поле
и выборы; менять UI для новой стратегии обычно не нужно. Сейчас 40 активных
профилей из 46 пользовательских описаний; 6 исключены из-за отсутствующих
лидеров. Всего 93 готовых состава. Обычные NPC используют перемешанный пул 40 пользовательских колод54–93;
все составы проходят до повторного перемешивания. Стартовые и фиксированные квестовые16–53 сюда не входят.

## Четыре слоя

1. **Карточные правила** — duelSession.ws, duelEffectRuntime.ws и файлы фракций.
   Они определяют допустимое действие и реально исполняют способность.
2. **Общая оценка** — OpponentStep, AiAbilityChoiceValue, TargetValue и выбор
   позиции в duelSession.ws. Считают немедленную пользу, урон, лечение,
   призыв, шпионов, допустимые цели и важность движков.
3. **Архетип** — CBetaGwentArchetypeAI в duelArchetypeAI.ws. Определяет
   приоритеты комбинаций, карты для будущих раундов, муллиган, сброс,
   воскрешение, копии, позицию и распределение по рядам.
4. **Пас и экономия карт** — duelAIPass.ws. Оценка добора очков после паса
   опирается на реальные прогнозируемые очки действия, а не его стратегический
   приоритет. duelWeatherAI.ws добавляет специальные решения морозной колоды.

**duelAICatalog.ws генерируется** из build_ai_rules.py: ID профилей/составов,
семейства, 70 зависимостей комбинаций, движки и финишеры. Редактируйте генератор,
а не результирующий WS. Все точные имена/замены можно проверить в rules.json
и ai_rules88_adaptation.md; источником roster служит deck_rules.txt.

## Ход обработки

Initialize определяет профиль по preset ID. Для собственного состава выбирает
похожий профиль по лидеру и совпадению количества копий. Refresh собирает
свою руку, колоду, поле/сброс и открытое поле противника. Затем OpponentStep
оценивает легальные кандидаты, добавляет Priority и резервные штрафы,
выбирает действие/место; последующие requests выбираются по тем же реальным
фильтрам правил. Для разыгранной карты обязательное окно выбора не пропускается.

ИИ знает свою руку/колоду и открытые зоны противника, размер его руки и колоды.
Скрытую руку/колоду игрока не читает. Долгого полного поиска на25–30 секунд
пока нет: текущий вариант — оценочные функции и зависимости.

## Очки и стратегический приоритет

Priority означает «это полезно сыграть раньше»: поставить движок до его
активаторов, собрать комбинацию, сберечь финишер. Этот бонус не добавляется
к счёту при расчёте догоняния после паса. **Реальное усиление способности
добавляется**: PublicDeployGain учитывает бойца Импера по открытым шпионам.
При силе6 и пяти шпионах он даст16, поэтому разрыв10 может закрыть одной картой.
Нельзя записывать в такие16 условную будущую ценность ещё не сыгранных шпионов.
Оценка сложных многоступенчатых способностей пока местами консервативна.

CopyValue(allCopies,target,forecast) разделяет реальное тело копии и прогноз
комбинаций. В погоне нельзя включать только предполагаемую будущую реакцию.
PileGain оценивает действительно доступные карты сброса; в пустом сбросе
воскрешение штрафуется. Закрытые засады не считаются уже набранной силой.

## Как добавить или изменить колоду

1. В deck_rules.txt задайте лидер, карты с количеством копий, основной план,
   муллиган, ранние/последние карты, цели контроля, пас и ошибки. Можно дописать
   пример «на поле X, в руке Y, счёт Z — лучше сыграть/пасовать».
2. В build_ai_rules.py проверьте aliases, replacements, family_for, связанные
   роли/списки. Замена должна быть явной и соответствовать роли строгой0.9.24;
   не создавать новый ID для отсутствующего лидера.
3. Перегенерируйте build_ai_rules.py → build_duel_catalog.py → build_full_catalog.py.
   Посмотрите changes у профиля в rules.json: исключённые копии, лимиты,
   чужие фракции и добранные карты. Проверьте получившийся список сами.
4. В duelArchetypeAI.ws добавьте условие в Priority/MulliganPriority/DiscardValue,
   если общая комбинация недостаточна. Для нового механического прогноза
   измените общую оценку в duelSession.ws и расчёт непосредственных очков.
5. Скопируйте изменённые WS в patch/проект, нативно скомпилируйте и упакуйте.
   Для выбора конкретного preset используйте DEV-режим; затем обычный NPC.

Стабильность важна: сохранённые/квестовые preset1–53 не перенумеровывать;
54–93 связываются с текущими профилями. Не давать обычному NPC квестовый
gold reward через случайный состав: награда определяется исходным native
deckName персонажа, а не выбранным случайным preset.

## Где искать типичные исправления

| Поведение | Файл / функция |
|---|---|
| Случайный состав обычного NPC | nativeGwentEntry.ws / BetaGwentNpcPreset; генератор / BetaGwentAIRandomPreset |
| Движок перед активаторами | build_ai_rules.py и duelArchetypeAI.ws / Priority |
| Сохранить финишер | KeyReserve / общая оценка |
| Плохой муллиган | MulliganPriority |
| Сброс Брана/Мышовура | DiscardValue |
| Выбор воскрешения | PileGain / AiAbilityChoiceValue |
| Ряд/соседство | PlacementAnchor / распределение рядов |
| Убить или заблокировать движок | EngineThreat / TargetValue / AiDamageChoice |
| Бессмысленно тратит несколько карт после паса | duelAIPass.ws и фактический action gain в OpponentStep |
| Пас после выигранного первого раунда | DryPass и общий pass policy |
| Способность карты исполнена неправильно | Карточный runtime; это не стратегия ИИ |

## Логи и проверки

LogChannel BetaGwent пишет решения AI/пас и события карточной цепочки.
check_ai_rules.py проверяет легальность составов, отдельные чистые функции
и пример догоняния бойцом Импера. check_pass_policy.py проверяет общий пас.
Эти проверки не заменяют партии и не гарантируют идеальную игру всех профилей.
Для отчёта приложите состав, раунд, счёт, размеры рук, открытое поле,
последние действия и ожидаемое решение. Это позволяет изменить конкретное
условие вместо случайного увеличения всех весов.
