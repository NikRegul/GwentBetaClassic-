# Этап81: отдельный редактор, имя колоды и цена паса

Причина неработающего входа подтверждена журналом REDkit:2026-10-04
18:27:37 `Failed to register menu 'BetaGwentBoard'`. Штатный DeckBuilder
загружал общий SWF, который регистрировался под другим именем.

Теперь у трёх входов отдельные корневые классы и native movie linkage:

| Вход | Корень | Ресурс проекта |
|---|---|---|
| Практика | BetaGwentBoard | betagwent_board.redswf |
| Редактор | BetaGwentDeckMenu → DeckBuilder | betagwent_decks.redswf |
| NPC | BetaGwentNpcMenu → GwintGame | betagwent_npc00.redswf |

Вход DeckBuilder из игрового меню выбирает libraryOnly, если нет запроса
NPC. В этом режиме бой не инициализируется; старт блокируется также в
WitcherScript. Вместо фона доски — однотонный экран редактора. Сохранение
возвращает в библиотеку собственных колод. Существующие8 слотов сохранены.

Исправление81d: OnGwintGameRequested в штатной игре сначала запрашивает
DeckBuilder. При pending/request=true этот вход должен быть предбоевым
выбором (mode2), иначе после его закрытия сцена остаётся с EMS_None.
В журнале19:45:59/19:46:36 подтверждён такой неверный editorOnly=true.
После настройки native входов восстановлены ResetFadeLock("GwintStart")
и FadeInAsync(0.2) из штатного CR4GwintBaseMenu. OnGwintGameEnded очищает
оба флага, а практика BetaGwentBoard всегда mode0, даже при старых флагах.
NPC-выход восстанавливает input context с contextCouldChange=true, как
штатный базовый гвинт. На NPC-переходе бой начинается после выбора колоды,
закрытие до боя сообщает штатный отказ, а не оставляет EMS_None.
Wcc81e подтверждён; игровой повторный проход NPC ещё требуется.

У имени есть кнопка «Изменить имя»: штатный OpenVirtualKeyboard, возврат
в редактор и лимит48 символов. Прямому полю также явно назначается фокус.
Новое имя остаётся черновиком до «Сохранить»; для записи колод на диск
по-прежнему нужен обычный игровой сейв. Пустой ответ штатного ввода не
перезаписывает имя. Отмена редактора не сохраняет черновик.

Обновления UI далее собирать комплектом:
`python tools/ui/build_menu_pack.py --apply`. Он последовательно собирает
три входа, проверяет ABC/receiver/36 функций и устанавливает ресурсы.
`--reuse-assets` допустим только если изображения/каталог не менялись.
GFx exporter пишет общие имена preview TGA: одновременные сборки в одном
каталоге не запускать. Свойства карт/досок берутся из общего AS-кода.

## Общая экономика раунда

Правила включены для всех составов через duelAIPass.ws/OpponentStep:

- После паса игрока уже выигранный раунд закрывается сразу.
- При допустимой ничьей ИИ не тратит карты ради лишних очков. Если ничья
  означает поражение в матче, он пытается выиграть.
- В первом раунде при0:0 коронах обычный бюджет погони — одна карта.
  Две допускаются, если останется хотя бы4 карты и преимущество хотя бы2.
- Потраченные карты считаются с момента паса игрока, а не с текущего хода.
  Реальный добор уменьшает чистую потерю руки.
- Лидер входит в план как действие без расхода карты руки; не обходит
  проверку паса. Прямой ответ/пара действий выбираются по цене руки и
  резерву полезных карт, затем по избыточному темпу.
- На решающем раунде разрешается дорогая погоня, если есть оценочный путь
  к победе. Если доступного темпа недостаточно, ИИ не выкидывает всю руку.
- Будущие тики погоды, рост, таймеры и предполагаемое Завещание после
  паса игрока исключены. Реальные немедленные эффекты остаются.
- Досрочный пас на своём преимуществе оценивает число ответных карт:
  публичный темп минимум25, отдельный запас25 для доступного лидера,
  поправки на видимые цели Игни/Казни/урона ряда. Требуются минимум2 ответа
  и предполагаемое преимущество руки. При короне игрока такой риск запрещён.

Это эвристика, не точная симуляция: пара карт может претендовать на одну
цель, неизвестные ответы/цепочки могут превысить публичный запас темпа.
Длинная погоня оценивается оптимистичной суммой; после каждого настоящего
действия план пересчитывается. Скрытая рука/колода игрока не читаются,
многотактный поиск до25–30секунд остаётся следующим этапом.

решающий раунд. Через NPC проверить отдельный вход/возврат. Новых
команд самопроверки ядра не требуется. Игровая приёмка81 пока ожидается.
