# 0.8.2: общий дефект выбора ряда и связанные карты

Проверяется только `BetaGwent/build/release082-final`, уровень ИИ 4.
Игровой код не изменён. Добавлен `tools/ai/check_row_choices082.js`.
Отчёт: `BetaGwent/build/audit082-20261018/row-choice-audit/report.json`.

## Причина

В `duelSession.ws:643`, `MonsterRequest`, для `kind == 3` ценность ряда равна
`CountLocation(rowSide, ids[i])`: предпочтение получает ряд с большим числом
карт. При равенстве остаётся первый вариант. Эта оценка не учитывает
способность карты, порог Игни, силу максимумов, величину усилений/повреждений,
броню, свободное место для создаваемого отряда и замену погоды.

Умение затем исполняется штатным обработчиком. У Игни проблема именно в
выборе ряда: проверка порога и уничтожение отрядов выполняются после выбора.
Поэтому он может правильно не сжечь ничего в неверно выбранном ряду.

Дополнительный точный поиск целей в `duelSession.ws:670` применяется к
`kind == 0` — выбору карты. Строковые запросы `kind == 3` эту ветку не проходят.

В погодном профиле есть специальное исключение Игни:
`duelWeatherAI.ws:215` вызывает `BurnValue`, учитывающий порог и сумму
сильнейших отрядов. Поэтому пресет 80 проходит оба примера Игни.
Для остальных рассматриваемых карт погодный профиль тоже возвращает число
карт в чужом ряду (`duelWeatherAI.ws:216`).

у Ирдена дополнительно подтверждена проблема выбора стороны.

## Метод проверки и пределы

Девять позиций запускаются под каждым из 46 неизменённых профилей:
414 сочетаний. Одна и та же специально заданная тактическая рука используется
для проверки общего механизма; она не объявляется штатной рукой всех колод.

Для каждого случая сначала исполняется обычный автоматический выбор ИИ.
Затем на заново созданных одинаковых состояниях явно выбираются допустимые
ряды и вызывается настоящий обработчик способности. Сравниваются реальное
изменение очков до начала следующего хода противника, наличие созданной
туши/ловушки и погодные токены. Тролль проверяется с обеими стадиями выбора:
исходный ряд и назначение. В тестах используются обычные отряды «Бес» без
способностей с заданной текущей силой/бронёй, чтобы исключить скрытые завещания.

Два случая Игни срабатывают на 45 профилях из 46. Остальные семь позиций
срабатывают на всех 46. Ошибок исполнения самого теста нет. Это 412
срабатываний нескольких общих дефектов, а не 412 отдельных багов.

Для погоды и Нивеллена измерен конкретный ближайший результат, а не все
будущие ходы. Для туши/ловушки доказан пропущенный доступный эффект создания;
их полная будущая тактическая ценность в этом тесте не оценивается.

Казнь идёт другим путём: `duelSpecials.ws:418` находит настоящие максимумы,
а `DamageScore` учитывает сторону. Приписывать ей обнаруженный дефект
подсчёта количества отрядов оснований нет. Это не означает, что все
остальные её стратегические решения уже проверены.

Запуск:

```powershell
node tools/ai/check_row_choices082.js
```

Ненулевой код возврата означает найденное отклонение либо ошибку исполнения;
подробности различаются полями `pass` и `error` в отчёте.

## Направление исправления

Общий запрос должен оценивать конкретную способность и допустимую сторону.
Игни — порог и сумму уничтожаемых максимумов; Ирден — суммарный результат
сброса силы/статусов на обеих сторонах; Бирна — действующие цели, броню и
прежнюю погоду; создающие карты — наличие места и будущую пользу;
Нивеллен — последствия перемещения; Тролль — совместно источник и назначение
с учётом теряемой погоды. Изменение только Игни оставит остальные ошибки.
