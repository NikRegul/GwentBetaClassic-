# Classic 1.32: полная сверка установленной цепочки и скрытые сообщения GFx

Пользователь подтвердил отказ fix7: просмотр колод блокирует движение героя,
камера остаётся активной, клавиши позволяют закрыть пустое меню; NPC-партия
застревает на загрузке. Игровой запуск по-прежнему выполняет пользователь.
Computer Use не применяется. Исправление пока не подтверждено.

## Структурная проверка

tools/classic132/audit_installed_pipeline.py читает именно установленный
modBetaGwentClassic132, не только выходные артефакты упаковщика. Отчёт:
BetaGwent/build/classic081-complete-audit/installed-audit.json.

- Установлен fix7. Других каталогов Mods и правил mods.settings нет.
- Весь набор установленных WS совпадает с подготовленными исходниками.
- 352 записи bundle проверены по диапазонам, отсутствию пересечений и CRC.
- Для каждого файла metadata сверены размеры, compression, offset, file ID,
  entry chain, bundle group и восстановленный из каталогов полный путь.
- 352 FNV64-записи отсортированы, содержат положительные и полные ID.
- У всех 345 CR2W версия 163, корректные CRC таблиц/чанков, cooked-флаги;
  GUID совпадают с cook.db и покрыты dep.cache SPED v2.
- Все menu import paths разрешаются внутри установленного bundle.
- Во всех 339 CSwfResource проверены границы GFx, отсутствие editor SWF,
  наличие AS3, связи ImageInfo с соответствующими inline-текстурами.
- Все 444 текстуры имеют проверенный Classic single-mip cooked layout.
- Max resource — 62.883685 МиБ, ниже проектного лимита 65 МиБ. Оба максимума
  allocation в metadata точно совпадают с реальным максимумом bundle.

14 проверок прошли. В обеих группах источников fix4 по пять идентичных Board
с UTF-8 BOM и CRLF. 33 теста Classic, 19 проверок bootstrap, 26 UI, 40 языка
и 309015 проверок аудиокаталога также прошли. Последние — статические/VM
проверки, не подтверждение нативного исполнения. Из DLC присутствуют штатные
bob, ep1, DLC1..16; ASI-файлов в bin/x64 нет. DLL-инвентарь сам по себе не
доказывает происхождение каждого бинарного файла.

## Что предыдущие контроли действительно показывают

NativeMenu-Control успешно вызвал MENU_CONFIG_BEGIN с нашим классом WS;
значит, класс меню и базовый мост работают со штатным Flash. Провал
CustomPath-Control не является окончательным доказательством запрета новых
путей: контроль собран до исправлений GUID и dep.cache. Его нельзя использовать
для утверждения, что именно новый каталог является причиной.

Два сценария пользователя остаются отдельными проверками. Отсутствие
MENU_CONFIG_BEGIN ограничивает поиск стадиями до регистрации Flash, но не
доказывает, что NPC-загрузка имеет ту же внутреннюю причину.

## Ограничения загрузчика

В Classic resources.ini MaxCompressedBudget=30, MaxUncmpressedBudget=70,
MaxRequests=32. У установленного NG бюджеты 30/70 тоже присутствуют,
MaxRequests=256. Classic bundle хранит большой GUI без bundle compression;
он занимает 62.9 МиБ. Сжатие zlib даёт около 36.3 МиБ, всё ещё больше 30.
Значения конфигурации не доказывают deadlock: неизвестны исключения для
одиночного крупного запроса и фактический маршрут загрузки. Конфигурация
игры не изменена; увеличение бюджетов не выдано за исправление.

## Проверка exe без запуска

Для чтения PE/RTTI установлены capstone 5.0.9 и pefile 2024.8.26 только в
BetaGwent/build/classic081-complete-audit/python-tools. inspect_loader.py
читает exe, не запускает и не меняет его. Выводы сохранены в loader-*.txt.

RTTI CScaleformLog: vtable 0x141f77f08, LogMessageVarg 0x14068b100.
Функция форматирует текст в буфер [rsp+0x50], удаляет завершающий newline,
создаёт временную строку и уничтожает её, не отправляя в OutputDebugString
или scriptslog. Поэтому прошлый OutputDebugString-сбор не мог дать эти
сообщения. Это подтверждено инструкциями exe, а не отсутствием строк в логе.

## Новый ручной сбор

BetaGwent/release/Classic132-Capture-Scaleform.cmd запускается пользователем.
tools/classic132/capture_scaleform.py наблюдает только собственный дочерний
процесс. В trace-points.json зафиксированы SHA exe и сигнатуры четырёх точек:

| Событие | RVA | Что читается |
| --- | --- | --- |
| FILE_OPEN | 0x689610 | URL Flash в RDX, вызывающий адрес |
| RESOURCE_RESOLVED | 0x689b87 | Результат поиска CSwfResource в RSI |
| FILE_RESULT | 0x689835 | Ненулевой файловый wrapper в RDI |
| GFX_MESSAGE | 0x68b14c | Уже отформатированный текст [RSP+0x50] |

Используются четыре аппаратные execute-точки DR0..DR3 на каждом потоке;
WriteProcessMemory, патчей инструкций и изменений файлов игры/сохранений нет.
При отключении восстанавливаются исходные debug registers. По тайм-ауту
процесс не уничтожается. Проверка выполнена на отдельном собственном Python:
все четыре точки на двух потоках, чтение аргументов, обычный exit и timeout
с последующим безопасным detach и продолжением дочернего процесса.

Self-test поймал порядок закрытия debug handles: DebugActiveProcessStop
делает их недействительными, поэтому ResumeThread теперь выполняется после
восстановления регистров и перед detach. Повторный self-test прошёл; оставшихся
тестовых дочерних Python с TRACE_SELFTEST_POINTS в command line нет.

Результаты ручного запуска будут записаны в
BetaGwent/build/classic132-scaleform-feedback/<timestamp>/scaleform.jsonl,
рядом scriptslog.txt, installed-before.json и result.json. Для этого сбора
достаточно один раз открыть колоды и закрыть игру; NPC-партию запускать не
нужно. Пока этот запуск не выполнен, фактическое место отказа загрузчика и
конструктора Flash остаётся непроверенным. Новый fix-архив не выпущен.
