# Classic 1.32: единый подробный сбор

Пользователь попросил собрать максимально подробные данные за один запуск,
чтобы прекратить последовательность коротких повторных проверок. Предыдущие
сборы были слишком узкими; дальнейший сбор объединён в отдельном инструменте.

## Последний результат gate-профиля

classic132-gate-feedback/20261016-153158-333484: exit 0, timeout false,
установленные файлы прежние. На 190.486 секунде RESOURCE_GATE имеет flags=32,
fileId=26654. RESOURCE_CLASS_RETURN вернул правильный CSwfResource, совпадающий
с global type pointer, abstract=false. RESOURCE_GATE_RETURN: startLoading=true,
flags=36. После этого Loader failed to open. Отказ поиска класса исключён
для данного запуска.

GetOrLoad вызывает 0x0978e0/0x097c90. Последний использует асинхронный метод
CBundleDiskFile (vtable +0x20 -> 0x092a20 -> 0x098a70), а предыдущий bundle
профиль следил за синхронным 0x098950/0xc8060. Поэтому отсутствие событий
синхронного reader не доказывает отсутствия попытки асинхронного чтения.
Это уточнение модели, не установленная причина отказа. Async reader/status
нужно наблюдать напрямую; новый игровой fix до этого не выпущен.

## Состав единого сборщика

tools/classic132/capture_all.py, launcher
BetaGwent/release/Classic132-Capture-All.cmd. Manifest с SHA exe, секциями PE,
сигнатурами 32 точек: classic081-complete-audit/all-trace-points.json.

- GetOrLoad/class lookup и результаты, flags и создание/отказ ресурса;
- dispatcher, асинхронный запрос, статус запроса/задачи, reader out pointer;
- sync/async bundle manager, выбранная runtime entry, merged FileInfo,
  entry chain, active bundle bitmap;
- динамически определяемый метод асинхронного bundle reader и его аргументы;
- физическое открытие, чтение заголовка CR2W, десериализация;
- GFx открытие/поиск/результат и ранее скрытые сообщения;
- на каждой подробной точке — все integer registers, 2 KiB стека,
  адреса возможных callers из exe, память по входным указателям;
- автоматически до двух полных снимков памяти, при первом отказе разных
  целевых файлов; fallback на сообщение Loader failed только если снимка ещё нет;
- SHA всех файлов установленных модов, script caches, ресурсы/настройки,
  scriptslog, исходный manifest и адреса/оригинальные байты точек.

Дамп пишется внешним Python-процессом через системный dbghelp.dll. Flags
0x21926: FullMemory, HandleData, UnloadedModules, ProcessThreadData,
FullMemoryInfo, ThreadInfo, IgnoreInaccessibleMemory. API/флаги сверены с
[MiniDumpWriteDump](https://learn.microsoft.com/en-us/windows/win32/api/minidumpapiset/nf-minidumpapiset-minidumpwritedump)
и [MINIDUMP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/minidumpapiset/ne-minidumpapiset-minidump_type).
Снимки остаются локально в classic132-full-feedback/<timestamp>; они дают
возможность разбирать heap/metadata/очереди и все потоки после закрытия игры.
Проверено 354 ГиБ свободного места; перед ручным запуском требуется минимум16.

## Отладочные точки и проверка

Четырёх аппаратных точек недостаточно для полного маршрута за один запуск,
поэтому новый сборщик использует временные программные CC-точки в памяти
собственного дочернего процесса. Файлы exe/мода/сохранений не записываются.
Игра запускается без DEBUG_ONLY_THIS_PROCESS. Сборщик ждёт Enter от пользователя
после загрузки сохранения до управления Геральтом и только затем подключается
через DebugActiveProcess. Глубокие точки включаются при целевом SWF.
При исполнении исходной инструкции остальные потоки НЕ приостанавливаются.
Точка возвращается после завершения всех уже зарегистрированных single-step
для её адреса. В коротком окне исходного байта параллельный вызов может пройти
без события трассы: полнота счётчиков при конкуренции не гарантируется.
При detach возвращаются исходные байты, сбрасывается временный TF, корректируется
RIP, если сбор прерван внутри callback. Исходная защита страниц восстанавливается
после каждого WriteProcessMemory. Для offline-разбора сохраняются адреса и
оригинальные bytes всех статических/динамических точек.

Self-test на собственном Python: пять точек, одна устанавливается динамически,
позднее подключение, 12 конкурирующих потоков / 1200 вызовов с проверкой return=42, полный dump
с теми же flags, проверка исходных code bytes изнутри дочернего процесса,
normal exit, timeout/detach, отмена через callback консоли и намеренная ошибка
внутри callback. Все пять сценариев прошли, дочерние процессы завершились с кодом0.
Перед длительным MiniDumpWriteDump временно возвращаются все исходные байты
и сбрасываются TF ожидающих потоков; после снимка трассировка продолжается.
Закрытие консоли / Ctrl+C запрашивает detach в основном потоке; Q тоже
отключает диагностику без закрытия игры. Ошибки записываются в collector-error.txt.
Python compile и
36 тестов Classic прошли. Игра агентом не запускалась, Computer Use не применялся.

Ручной запуск пользователя: загрузить мир, Enter в консоли, колоды; при возможности вернуться в мир — NPC
в этом же запуске. После «Снимок памяти сохранён» игру можно закрыть, затем
дождаться «Готово». Во время dump возможна краткая пауза. До результата
этого запуска Classic остаётся неработающим fix8, без заявления об исправлении.

## Регрессия сборщика: загрузка сохранения

Запуск 20261016-155326-267702: пользователь сообщил, что сохранение не загружалось
до закрытия консоли. Последнее событие GFX_MESSAGE на 115.938 секунде — loading
hint; DEEP_TRACE_ARMED и MEMORY_DUMP отсутствуют. result.json отсутствует после
принудительного закрытия. Этот запуск не дал новых данных по отказу гвинта.

В прежнем single-step приостанавливались все прочие потоки. Два уже поставленных
в очередь breakpoint event могли приостановить друг друга до single-step,
создав цикл ожидания. Это выявленный дефект сборщика и вероятное объяснение
регрессии сохранения; стек зависших потоков не был сохранён, поэтому причину
конкретного зависания считаем неподтверждённой. Старое зависание гвинта
наблюдалось и без данного сборщика, эта правка его исправлением не является.

Исправление и проверки: self-test-20261016-161442-793664. В concurrent-attach
все вызовы вернули 42, исходный код проверен изнутри дочернего процесса.
Файлы игры, мода и сохранений данной правкой не менялись; игра агентом не запускалась.
Семантика позднего подключения и управление событиями сверены с
[DebugActiveProcess](https://learn.microsoft.com/en-us/windows/win32/api/debugapi/nf-debugapi-debugactiveprocess),
[ContinueDebugEvent](https://learn.microsoft.com/en-us/windows/win32/api/debugapi/nf-debugapi-continuedebugevent)
и [SetConsoleCtrlHandler](https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler).
