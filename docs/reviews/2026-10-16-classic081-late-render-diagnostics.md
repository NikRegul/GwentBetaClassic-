# Fix11 отклонён: требуется состояние после создания GFx images

Пользователь подтвердил тот же невидимый UI после fix11. Новый запуск:
`BetaGwent/build/classic132-full-feedback/20261016-204339-830438`.
438 событий, штатный выход, восстановлены временные инструкции, файлы игры
и мода не изменились. ATLAS_STATE подтверждает новый native-bitmap путь для
10,11,12,14,15,17,18,20 и ожидаемые размеры. Для карточных атласов BitmapData=null,
поэтому старый путь уже использовал native Bitmap fallback. Fix11 не принят.

Все 30 CSwfTexture и CRenderTexture присутствуют. Отличие hash-поля CRenderTexture
между UI и картами объясняется inline/external хранением: в fix9 внешние UI
имели ненулевые hash, но также не показывались. Это не причина дефекта.
В штатном Classic inline-текстуры имеют export parent=1; наши исходные чанки
имеют parent=0. Это различие зафиксировано, но не объясняет неудачу fix9, где
все текстуры были внешними. Оно пока не является основанием нового патча.

Дамп state-loaded снимается в RESOURCE_LOAD_RESULT, до создания GFx изображений
и обработки очереди рендера. Он подтверждает загрузку и содержимое ресурса,
но не устанавливает фактическую привязку видимых Bitmap к GPU-текстуре.

Обновлён capture_all.py: максимум четыре снимка, ранний и поздний для колод
и партии. Поздний запрос через DebugBreakProcess выполняется через пять секунд
после раннего; код и TF перед записью восстанавливаются по существующей схеме.
Меню нужно оставить открытым до state-rendered. Сигнатуры шести новых точек
сверены с SHA установленного exe и его PE; генератор add_image_trace.py.

- GFX_IMAGE_BINDING: имя из GFx::String при LoadExportedImage.
- GFX_TEXTURE_LOOKUP_RESULT: результат поиска CSwfTexture.
- GFX_IMAGE_TEXTURE: фактическая текстура, linkageName и renderProxy.
- GFX_IMAGE_CREATED: возвращённый GFx image object и RTTI.
- GFX_IMAGE_FILE / GFX_IMAGE_FILE_CREATED: отдельный путь загрузки внешнего image.
- RENDER_SNAPSHOT: адрес корня меню для чтения позднего дампа с --resource.

Контрольные функции взяты из установленной 1.32, CScaleformImageCreator,
CSwfResource и локальной RTTI/дизассемблирования; компьютерный интерфейс не
использовался. Поздний снимок протестирован на отдельном Python-процессе:
две записи дампа, корректное продолжение, отсоединение, проверка исходных
инструкций дочерним процессом. Также прошли существующие проверки 12 потоков,
1 200 вызовов, завершения, исключения callback и закрытия консоли.

Мод остаётся установленным fix11. Новый кандидат не подготовлен без данных,
которые отличают ошибку поиска изображения от GPU-загрузки или обрезки.
