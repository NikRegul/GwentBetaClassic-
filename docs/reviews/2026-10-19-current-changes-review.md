# Проверка текущих изменений 0.9.0 и CleanBuild

Проверены подготовленные исходники сборки 7, переносимый CleanBuild и их отличия. Игровой сеанс не запускался. Код мода в ходе ревью не исправлялся.

## Найденные проблемы

1. **P1 — CleanBuild снова создаёт невидимые баннеры.** В `CleanBuild/tools/features082/build_banners090.py:83` внешний ImageInfo (1009) записывается до SDK ExporterInfo (1000). Исправленный основной генератор записывает их в обратном порядке. В результатах полной переносимой сборки `tmp/Portable Clean Build/BetaGwent/build/20261018T210923Z-7e514121/banners/classic/resources` все 18 страниц имеют старый порядок; в `banners090-sdk-fix5` ни одна страница его не имеет. Порядок уже связан с отсутствием баннеров в игре и исправлен в сборке 6; её видимость на Classic подтверждена в `BetaGwent/release/0.9.0_CURRENT_RU.md`. Перенести исправление порядка тегов в автономный генератор, затем пересобрать страницы и оба пакета. Проверка CRC и совпадение с прежним результатом эту ошибку не выявляют.

2. **P2 — загрузчик CleanBuild отвергает позднюю нативную текстуру.** В `CleanBuild/BetaGwent/ui/src/BetaGwentBanners090.as:37` COMPLETE с нулевыми размерами сразу вызывает отказ. Та же реализация находится в `CleanBuild/source/classic-ui/src`. Исполнение существующего `check_banner_runtime3_090.js` с чтением именно этих исходников воспроизвело сбой `late native texture swaps banner and power together`: после появления размеров на следующем ENTER_FRAME баннер уже удалён. В новой реализации есть ожидание до 90 кадров. Исправление генератора из пункта 1 не исправит этот независимый случай; нужно синхронизировать оба исходных загрузчика и связанные методы поля.

3. **P2 — в автономный комплект не попали два исправления способностей.** Экспортёр `tools/export_clean_build.py:39` берёт WitcherScript из final5. В `CleanBuild/source/scripts/game/betagwent/duelNeutral.ws:39` Миргтабракке получает две атаки вместо трёх, а в `duelNilf.ws:144` Харальд — девять вместо десяти. Сценарий с одним противником силой 100 и без брони исполняет настоящий транспилированный розыгрыш: CleanBuild наносит соответственно 4 и 9 урона; `release090-scripts7` — 6 и 10, без незавершённых запросов или fatal. Нужно перенести исправленные источники в комплект и обновить его экспорт; UI сборки 7 также отличается от комплекта в трёх AS-файлах на каждой платформе.

4. **P2 — отдельная команда проверки выбирает устаревший выпуск.** `Verify-0.9.0-Final.cmd:3` не задаёт BG_FINAL, а `verify_final090.py` по умолчанию проверяет `release090-final`. Новые Build-0.9.0-Final6/7.cmd устанавливают BG_FINAL внутри setlocal, поэтому после их завершения выбор не сохраняется. Запуск отдельного Verify может подтвердить старые архивы, даже когда новый кандидат отсутствует или повреждён. Нужен явный параметр ревизии либо отдельный проверяющий вход для текущей сборки.

## Выполненные проверки

- CleanBuild preflight: инструменты и все закреплённые подготовленные входы прошли проверку.
- Все исходники и вспомогательные инструменты CleanBuild совпали с source-manifest ранее выполненной полной переносимой сборки; повторной полной компиляции комплекта в этом ревью не было.
- Три теста контейнеров и безопасной очистки CleanBuild прошли. Создание тестовой junction требовало выполнения вне файловой песочницы; тест подтвердил сохранность её отдельной цели.
- 28 наборов регрессий реальной транспилированной игровой логики из CleanBuild прошли, включая скрытую информацию, преследование после паса, выбор целей, броню, создание и возвращение карт.
- Выбор ряда: 9 сценариев на 46 архетипах, 414 результатов без ошибок. Дополнительно 93 тактических сценария на архетипах 54/73/99 прошли. Обёртка разрешала новый путь замороженных исходников CleanBuild; логика сценариев не изменялась. Первый запуск теста рядов с неверным форматом CLI прочитал старый baseline 0.8.2; он исключён из результата и повторён с правильными именованными аргументами.
- UI сборки 7: баннеры 370, импорт 55, вставка Windows 80, копирование 38 — все 543 проверки прошли.
- На исходниках CleanBuild импорт 55 и вставка 80 также прошли; поздняя загрузка баннера из пункта 2 не прошла.
- У обеих исходных версий BetaGwentBoard.as в CleanBuild сохранены UTF-8 BOM и CRLF. Проверки UI сборки 7 подтвердили пять зеркальных копий каждой платформы.

Во время ревью завершились новые компиляции сборки 7: отчёт Classic содержит compilePassed=true, errors=[], timedOut=false; Next-Gen — exitCode=0, completedByOutput=true, неизменённые patch sources. Созданы четыре меню каждой платформы. Это проверка отчётов и файлов, а не запуск игры.

Упаковка сборки 7 завершилась во время ревью. Независимо проверены оба итоговых ZIP из `release090-final7/package-candidate/archives-optional`: SHA-256 самих архивов совпали с sidecar, CRC всех записей верен, имена уникальны, манифест полностью покрывает содержимое и SHA-256 каждого файла совпадает. Classic — 104 записи, Next-Gen — 47. Штатный `verify_final090.py` с явным BG_FINAL=release090-final7 также прошёл все 25 проверок.

Сырые результаты текущего прогона: `BetaGwent/build/review090-20261019/`: `checks-summary.json`, `rows/report.json`, `tactics/report.json`, `banner-tag-order.json`, `reproductions.json`, `packages.json`. Проверки показывают, что исправления присутствуют в новой сборке 7, но автономный CleanBuild ещё содержит перечисленные старые реализации. Внутриигровая проверка остаётся отдельным шагом.
