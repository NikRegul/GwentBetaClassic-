# Classic 1.32: повторный вылет редактора 0.9.0

## Подтверждено

Установленные файлы основного мода и DLC совпали с опубликованным локальным
архивом (88 файлов). В первом полном сборе все 30 изображений успешно
создались; это не установленный случай отсутствующей текстуры.

Правильный GFxExport ExporterInfo для 13 языковых файлов сохранил байткод,
глифы и привязки побайтно, но сам по себе НЕ устранил падение.
Новая трасса: `BetaGwent/build/classic132-full-feedback/20261018-174231-955853`.

Исключение снова в RVA 0x150acb6. Стек содержит вызов из RVA 0x14ff930:
обработчик берёт индекс локальной переменной, преобразует значение в Number
и вычитает единицу. В дизассемблированном ABC четырёх меню Number declocal
встречается только в трёх циклах `BetaGwentTextLanguage.layoutButton`.

В новом варианте эти три `size--` заменены на ограниченное явное вычитание
через Math.max. Все восемь меню скомпилированы; Number declocal отсутствует
в их готовом ABC. Пять исходных копий каждой платформы совпадают, BOM/CRLF
сохранены. Проверки интерфейса check_polish138: 117 пройдено.

Накладка для повторного теста содержит четыре меню и 13 языковых ресурсов.
Байты текстур, старые прямоугольники изображений, импорты и GUID сохранены;
каждое меню укладывается в 32 МиБ. Кэш зависимостей прежний, основная сборка
и DLC остаются поставщиками внешних ресурсов. Состав bundle проверен по SHA.
Установленные четыре файла накладки совпали с подготовленными по SHA.

## Ещё требуется

Пользователь подтвердил открытие редактора, смену языка и NPC-партию после
обхода Number declocal. Сначала проверялась только накладка интерфейса;
затем, после закрытия игры, отдельно установлены 81 файл уже скомпилированных
скриптов с фиксом Изенгрима, очисткой и BG1_EXPORT. Проверка именно этого
обновлённого сочетания скриптов ещё не подтверждена. Основные архивы пока
не заменены.

Копирование через Flash и Ctrl+C по сообщению пользователя не работает в
системный буфер. Помощник Copy-Deck-Code.cmd читает последнюю BG1_EXPORT,
проверяет её целиком и явно пишет Windows clipboard. Добавлены совместное
чтение активно записываемого лога и отказ от копирования старого кода, если
последний экспорт повреждён. 9 сценариев прошли; реальный Set/Get-Clipboard
через рабочий помощник подтвердил код со скриншота (25 карт). Это не проверка
нового игрового экспорта и не исправление нативного Flash-буфера.

Отдельно проверка кода обнаружила слабое место сообщения очистителя:
предупреждение о не удалившихся стеках сразу сопровождается общей инструкцией
удаления мода. Перед финальной упаковкой нужно объединить результат в одно
сообщение и проверить ветку отказа RemoveItem. Текущие проверки очищения
не заменяют настоящий цикл сохранения/загрузки .sav.
