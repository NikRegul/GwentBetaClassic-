# Classic 0.8.1: оформление остаётся невидимым после fix10

Пользователь подтвердил, что fix10 не восстановил оформление колод. Снимок
показывает деревянный заголовок, тексты и большую карту справа, но отсутствуют
фон, бумага, миниатюры списка, рамки и большинство кнопок. Fix10 не принят.

Свежая запись: `BetaGwent/build/classic132-full-feedback/20261016-202725-174011`.
Сборщик завершился штатно: 438 событий, один полный дамп, executable и
установленные файлы не изменялись, временные инструкции восстановлены.
В scriptslog есть BOARD_CONFIGURED, NATIVE_GWENT_MENU_READY,
BOARD_ARTWORK decoded=46 failed=0 и BOARD_CLOSED. Ошибок открытия вспомогательных
SWF в этой записи нет; это не подтверждает все языки и все страницы лидеров.

`texture-state.json` из `state-loaded-26654.dmp` подтверждает все 30 CSwfTexture:
правильные linkageName, размеры, ненулевые объекты рендера. После fix10 UI снова
inline (fileObject=0), девять карточных атласов внешние (загружены, flags=2).
Следовательно, возврат UI в inline сам по себе не устранил проблему. Ненулевой
объект рендера и счётчик AS не доказывают видимый результат отрисовки.

Следующая проверяемая гипотеза — использование BitmapData из связанного
нативного GFx/DDS-изображения. Старый общий путь создаёт Bitmap от сохранённого
BitmapData и затем предпочитает graphics.beginBitmapFill; успешный вызов без
исключения считается успешно показанной картинкой. Это может скрывать сбой
в конкретной реализации Classic. Причина ещё не доказана в игре.

Кандидат fix11 меняет путь только для страниц оформления
10,11,12,13,14,15,16,17,18,20: новый экземпляр встроенного Bitmap для каждого
фрагмента, scrollRect в физических пикселях и один масштаб контейнера. Его
BitmapData не читается. Карточные страницы 0–8, поле 9, погода 19, эффекты и
кеговые страницы сохраняют старую отрисовку. Классы боевых эффектов не меняются.
Для каждого реально использованного атласа один раз пишется ATLAS_STATE с
номером страницы, размером Bitmap/BitmapData (если старый путь) и маршрутом.

Пять изолированных копий Board и HDArt находятся в classic081-bitmap-fix11;
Board сохраняет UTF-8 BOM/CRLF. Canonical UI и принятый пакет Next-Gen не
изменяются. В установленных ресурсах заменяется только native GFx четырёх
меню; пиксели, inline-чанки, внешние текстуры, их ссылки и размеры сохраняются.
Метаданные пересчитываются по новым размерам. Ограничение каждого запроса
32 МиБ продолжает проверяться. Все остальные 384 payload сохраняются.

До подтверждения пользователя fix11 остаётся кандидатом. Commit/push и работа
над 0.8.2 следуют только после полноценной проверки Classic.

## Проверка и установка кандидата

Четыре меню скомпилированы, native-bitmap и ATLAS_STATE присутствуют в каждом
ABC. Сравнение исходников подтверждает: изменены только Board (вывод лога) и
HDArt; остальные AS-классы совпадают с fix4. В пяти компилируемых копиях Board
сохранены BOM/CRLF. Проверка кандидата и установленного мода: 16 условий без
ошибок, 388 payload, 381 CR2W, 339 SWF, 444 текстуры, максимум 32 679 884 байта.
Fix11 установлен с проверкой SHA; fix10 сохранён в installed-before. GUI DLC
сохранил прежние SHA. Игра агентом не запускалась.

Первая попытка установки завершилась до замены файла из-за преобразования
PowerShell `$null` в пустой путь для File.Replace. Исходные файлы восстановлены;
установщик использует явный путь дополнительной копии и принимает только
временный файл с известным SHA. Повторная установка и аудит прошли.

Игровой результат пока ожидается. Один запуск через Classic132-Capture-All.cmd:
после загрузки мира Enter в консоли, затем колоды, редактор, NPC-партия и выход.
В scriptslog должны появиться ATLAS_STATE для всех реально использованных страниц.
