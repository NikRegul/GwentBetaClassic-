# Полные позиции и воспроизведение — первый этап 0.9.4

`tools/ai/position_replay094.cjs` сохраняет и проверяет полную позицию существующего общего движка WS→JS. Новой реализации правил, .NET/RPC или игровых изменений нет. Это инструмент локального исследования; игровая запись полного состояния пока не подключена.

## Что работает

- `capture` оборачивает полный packed-state существующего `runtime.serialize(game)` в fixture с явным происхождением, SHA состояния, fingerprint правил и SHA исполняемых файлов снимка и сериализатора.
- `replay` восстанавливает fixture и исполняет заданные действия через авторитетные методы общего движка. В отчёте есть исходные/итоговые счёт, руки, раунд, RNG, журнал и SHA итогового состояния.
- Без файла действий `replay` выполняет подготовку и один ход нынешнего Hard. Это исследование решения текущей политики, а не воспроизведение исторического выбора.
- Поддержаны розыгрыш, размещение перед картой, цель/ряд, лидер, пас, переход раунда, выбор/завершение целей, выбор шаблона и муллиган. Недопустимые действия дают техническую ошибку; они не считаются поражениями.
- Результаты создаются исключительно в новых файлах. Существующие fixtures и отчёты не перезаписываются.

## Границы достоверности

Обычные `AI_POSITION`/`AI_POSITION_CARDS` содержат только часть состояния: нет всей очереди, частных полей карт и полной позиции RNG. Такие данные **отклоняются**, а не дополняются предположениями. Сначала сохранять исходный журнал через `audit_ai_log198.py`; импорт журнала в полный fixture остаётся отдельной будущей задачей.

Сериализатор существующего движка исключает кеши клонера и визуальные кадры. Инструмент проверяет ссылки графа, типы, RNG, опасные ключи, SHA и точный структурный round-trip deserialize→serialize; пропавшие поля с начальными значениями отклоняются. Это строгий контракт текущего стенда, не доказательство совпадения с историческим нативным исполнением. Устаревший fixture с иной схемой может быть отклонён; автоматической миграции нет.

Полный fixture содержит скрытую руку/колоду для восстановления правил. Политика остаётся штатной Hard и сохраняет её ограничения информации. Полный fixture не превращает Hard в open-info. «Классическая» с её более широким доступом требует собственного контроллера: `mode=classic` и external-policy состояния отклоняются. Флаги `aiOpenInfoBench` и `aiSimulating` также отклоняются. Инструмент не сравнивает силу этих режимов.

Записанная последовательность действий воспроизводится с SHA результата. Поиск Hard использует временные бюджеты и может зависеть от нагрузки хоста; равенство решений между разными нагрузками не обещается. Отчёт явно содержит `hardChoiceMayDependOnHostTiming`, `notStrengthResult=true`, `historicalRuntimeVerified=false`, `nativeGameplayVerified=false`.

## Команды

Сначала создать свежий замороженный снимок по `AI_DEVELOPMENT_RU.md`. Команды ниже используют уже подготовленный проверочный снимок:

```powershell
node tools/ai/check_position_replay094.cjs BetaGwent/build/improvements094-review-20261026-01/rules BetaGwent/build/replay094-NEW
```

Проверка создаёт синтетическую позицию на настоящем движке, проверяет round-trip, SHA двух повторов записанного паса, прямой авторитетный результат, нынешний ход Hard, отказ на частичный журнал, отсутствие RNG/поля матча, повреждённую ссылку/SHA, чужие правила, Classic/external-state и перезапись. Это не человеческая партия.

Для полного packed-state из того же снимка:

```powershell
node tools/ai/position_replay094.cjs capture <rules> <state.json> <new-fixture.json> "описание происхождения"
node tools/ai/position_replay094.cjs replay <rules> <new-fixture.json> <new-report.json> <actions.json>
node tools/ai/position_replay094.cjs replay <rules> <new-fixture.json> <new-hard-report.json>
```

Допускается `.json.gz` на входе. Файл действий — JSON-массив, например `[{"kind":"pass","side":2}]`. `request` — настоящий ID текущего запроса, `item` — выбранный ID. При смене правил/сериализатора нужен отдельный явно подготовленный fixture; заменить fingerprint вручную недостаточно.

Для подключения нового воспроизведения в JS-стенд доступны экспортированные `makeFixture(runtime, snapshot, game, source)` и `replay(snapshot, fixture, actions)`. Первая функция требует Host strength/matchStrength=4 и полный штатный Hard session. Для вычисления одного решения нужен устойчивый ход стороны 2 без ожидающего запроса/перехода раунда.
