# Улучшение и проверка ИИ

## Архитектура

Hard и «Классическая» используют один движок правил WitcherScript, переводимый в JS для испытаний. Исходный ИИ беты переносится по пути C# **как читаемый исходник → JS → WS**. .NET, native-host, RPC и параллельные реализации правил не использовать.

Hard сохраняет ограничения скрытой информации. «Классическая» может читать скрытую руку/колоду. Сравнения должны прямо указывать эту асимметрию. Тестовый open-info Hard не включать в игре.

Прямой порт находится в `tools/ai/beta_js092`, WS — в `BetaGwent/development/scripts/game/betagwent/betaOriginal*.ws`. Подбор содержит 24 исходных имени / 17 эффективных групп на 109 presets и 92 уникальных составах. Это выбор по конечной выборке, а не доказательство глобально сильнейших профилей. Данные и исходный SHA плана подтверждения хранятся в `data/beta924/ai/validation093`.

Оригинальные C# материалы для чтения сохранены локально в `BetaGwent/build-inputs/reference/beta-original-csharp`; их лицензия не подменяется лицензией нашего порта, в публичный экспорт они не включаются.

## Порядок работы

1. Сохранить игровой журнал и версию/сложность/seed. Восстановить конкретную позицию: состав руки, поле, состояния, доступные цели, очередь, использованный лидер.
2. Сформулировать причину и независимое ожидаемое поведение. Добавить позицию в `tools/ai/fixtures` и регрессию; не кодировать только выбранный сейчас ответ без проверки его последствий.
3. Исправить минимальную общую причину. Если ошибка правил — исправлять общий WS/JS движок. Для Hard проверить независимость от истинной скрытой руки/засады.
4. Обновить клон генератором, заморозить отдельные входы. Не менять код/seed/профили во время идущего сравнения.
5. Прогнать адресный тест и общие регрессии. Для оценки силы — отдельные development и заранее отложенный holdout, одинаковые раздачи/зеркала/составы и контроль A/A. Ошибка не считается поражением.
6. Принять улучшение только по заранее выбранным критериям. Отрицательные и неопределённые результаты честно сохранить. Общий процент побед не заменяет проверку найденного бага.
7. Проверить JS/WS соответствие, оба нативных компилятора и реальную игру. После этого делать новый релиз по [BUILD_RU.md](BUILD_RU.md).

## Основные команды

```powershell
python -X utf8 tools/ai/gen_clone.py
python -X utf8 tools/ai/snapshot.py BetaGwent/build/ai-candidate-NEW/rules
python -X utf8 tools/ai/validate091.py BetaGwent/build/ai-candidate-NEW/rules BetaGwent/build/ai-candidate-NEW/regressions --workers 4
node tools/ai/check_aim_choices093.cjs
node tools/ai/check_playtest_ui093.cjs
```

Для длинных сравнений смотреть `tools/ai/run_comparison093c.py --help` и `tools/ai/accept_candidate093c.py --help`. Исторические данные 0.9.3c не являются оценкой силы последующих изменений.

Для новой сетки на выбывание:

```powershell
powershell -File tools/ai/Start-Classic093Tournament.ps1 -Build BetaGwent/build/ГОТОВЫЙ_РЕЛИЗ -Output BetaGwent/build/НОВЫЙ_ТУРНИР -Grids 16 -Workers 4
```

Составы, правила, seed, формат и объём замораживаются до начала. Завершённую сетку не запускать заново и не менять. Повышать параллелизм только после проверки совпадения решений: wall-clock cutoff поиска чувствителен к нагрузке.

## Открытые направления

- Анализ фактических проигрышей и пустых способностей; резерв реактивных карт и стоимость ответа/паса.
- Свежие журналы сначала сохранять: `python -X utf8 tools/ai/audit_ai_log198.py "путь/scriptslog.txt" "новый-каталог-свидетельств"`. Индекс сохраняет исходник, номера строк, 13 полей карт и решения. Это не полный повтор исторического runtime и не автоматическое доказательство ошибки. Утверждение о баге требует позиции, прежнего ошибочного выбора и проверяемой альтернативы.
- Оценка линий на следующих раундах, засады без чтения настоящей личности, стоимость риска.
- Полный open-info потолок пока не доказан; не делать вывод об информационном проигрыше из неполной реализации.
- Сохранение журнала в facts требует отдельного контракта и игровой проверки; пока не реализовано.
- Проверка времени решений и интерфейса на Steam Deck и слабых CPU.

Подробности последнего изменения: [AI_IMPROVEMENT_093_AMBUSH_RU.md](AI_IMPROVEMENT_093_AMBUSH_RU.md). Перед правками эффектов читать [VFX_RENDERING_RULES_RU.md](VFX_RENDERING_RULES_RU.md).
