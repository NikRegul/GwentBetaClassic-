## Входы

- Python 3 и Node.js в PATH.
- Локальные `BetaGwent/build-inputs` и `BetaGwent/toolchains` согласно [BUILD_INPUTS_RU.md](BUILD_INPUTS_RU.md). Игровые ресурсы, SDK, голоса и оригинальные материалы в публичный Git не входят. Одного клонирования Git недостаточно для упаковки игровых архивов.
- Канонические скрипты: `BetaGwent/scripts` и `BetaGwent/development/scripts`.
- Каноническое меню: `BetaGwent/ui/src`. Изменения Board повторяются в пяти копиях с UTF-8 BOM и CRLF; шаблон Classic — `tools/features091/BetaGwentBoard_classic093.as`.
- Профили и составы: `data/beta924/design/beta_ai_profiles093.json`, `data/beta924/ai/validation093`. Старый `drafts/state.json` для сборки не требуется.

## Команды из корня проекта

```powershell
python -X utf8 tools/recon/check_project_layout.py --hash-inputs
.\Build-0.9.5.cmd
```

Обычный запуск создаёт новую папку `BetaGwent/build/release095-<дата>-<время>`. Проверяет замороженные правила, все группы из `tools/ai/validate091.py`, реальные партии, соответствие JS/WS, оба нативных компилятора, меню, языки и голоса. Проверки сохранений включают перенос старого профиля, целостность чисел и текста, сохранение карантина и исходных повреждённых данных, защиту неизвестного формата и доставку store в подготовленные скрипты обеих платформ. Завершает упаковку и независимую сверку SHA-256/CRC. Длительность значительная; логи находятся внутри новой папки сборки.

Продолжить конкретную незавершённую сборку можно только явно:

```powershell
.\Build-0.9.5.cmd --out BetaGwent/build/МОЯ_ПАПКА --resume
```

После изменения исходников нужен новый выходной каталог. Готовые релизы и замороженные входы сравнений не изменять. При ошибке сначала читать последний лог; существование ZIP само по себе не означает успешную сборку.

Если нативный компилятор Next-Gen (`wcc_lite`) остановился, не начав выдачу лога, `tools/features082/compile_nextgen_final090.py` прерывает попытку через 120 с простоя (`--stall`) вместо ожидания общего лимита 600 с и пишет в `compile-nextgen-final/result.json` последние строки stdout и `wcc.log` — по ним видно, в какой подсистеме завис процесс. Неудачная попытка не блокирует продолжение: `--resume` повторяет этот шаг, а прежний каталог сохраняется рядом как `compile-nextgen-final.failed-N`. Успешную попытку повторная сборка не перезаписывает.

Если сборка упала позже заморозки входов — на компиляции AS-меню: `tools/features091/build091.py` вызывает `prepare_ui091.py` только при отсутствии каталога `<out>\ui-sources`, поэтому после правки Board-исходников перед `--resume` его нужно удалить (`rmdir /s /q BetaGwent\build\МОЯ_ПАПКА\ui-sources`). Иначе следующий шаг возьмёт прежние развёрнутые копии и повторит ту же ошибку компиляции. Новые SHA канонического `BetaGwent/ui/src/BetaGwentBoard.as` и Classic overlay должны быть закреплены в `tools/features091/prepare_ui091.py`; рассогласование ловит `python -X utf8 tools/recon/check_project_layout.py`.

Независимая проверка готового результата:

```powershell
python -X utf8 tools/features093/verify093.py BetaGwent/build/МОЯ_ПАПКА --version 0.9.5 --user-release
```

Готовые файлы 0.9.5 находятся в `release/0.9.5` (если такая папка уже есть — в новом `release/0.9.5-2`, `-3` и т. д.; готовые архивы не затираются): два архива для 1.32 и 5.0+, SHA-256, описания/пост/changelog на 13 языках, отчёты и игровой checklist. Предыдущая завершённая сборка 0.9.4a — `release094a-20261027-final01`, выдача `release/0.9.4a-2`. Сборщик ничего не устанавливает и не публикует.

Формат профиля 2 сохраняет четыре поля, проверяет текст вместе с числовыми данными и читает прежний формат 1. На Classic 1.32 дополнительно сохраняются прежние поля; откат на 0.9.3 после сохранения в 0.9.4 не поддерживается. Утерянные данные можно восстановить только из доступной целой копии. Обязательна отдельная игровая проверка «сохранить — выйти — загрузить»: автоматические проверки и нативная компиляция не подтверждают сериализацию в самой игре. Причины потери, закрытые случаи и трактовка лога: [SAVE_STORE_094_RU.md](SAVE_STORE_094_RU.md).

Историческое исправление ИИ 0.9.4 проверено на разработческой выборке из 368 партий: 50%, ошибок нет. Отложенная выборка не запускалась; это не оценка силы 0.9.5 и не доказательство общего прироста. Для нового паса 0.9.5 проверяются адресные позиции, общая регрессия и полные партии; отдельного сравнения силы development/holdout не проводилось. Hard сохраняет ограничения скрытой информации, у «Классической» доступ шире.

## Что можно удалять

Временные логи, кэши Python, прерванные выходы и повторные распаковки можно удалять после проверки зависимостей. Не удалять постоянные входы, toolchains, текущий готовый релиз, выбранные базовые снимки сравнений, регрессионные fixtures или результаты незавершённого исследования. Каталог `BetaGwent/publication` — отдельный checkout публичного Git, а не временная папка.

## Публичный Git

Этот раздел относится к авторскому рабочему каталогу с ресурсами. В обычном клоне GitHub работать с Git напрямую, без export_public_sources.py.

Рабочий каталог содержит локальные игровые ресурсы и имеет отдельную историю. Публичный репозиторий — source-only checkout `BetaGwent/publication` с origin `NikRegul/GwentBetaClassic-`. Не отправлять в него нефильтрованную историю рабочего каталога.

После проверки текущих исходников:

```powershell
python -X utf8 tools/recon/export_public_sources.py
python -X utf8 tools/recon/export_public_sources.py --apply
```

Первый запуск показывает план; второй синхронизирует допустимые исходники и удаляет устаревшие публичные копии, проверяя содержимое на ключи и крупные ресурсы. Перед коммитом просмотреть diff. Инструмент не делает commit/push. Fetch и последующий обычный fast-forward push выполняются отдельно, без force. Исходные ветки и пользовательские изменения нельзя затирать.

Если локальный UI ещё в работе, можно явно выбрать ранее проверенную пару через `--ui-snapshot <каталог>`: в каталоге должны лежать `BetaGwentBoard.as` и `BetaGwentBoard_classic093.as`. Экспорт повторит Board в пяти публичных копиях, проверит BOM/CRLF и действующие SHA в `prepare_ui091.py`; локальные файлы не изменятся. Этот параметр нужен и при просмотре плана, и при `--apply`.

В чистом публичном checkout без игровых ресурсов доступны `python -X utf8 tools/recon/check_project_layout.py --sources-only` и проверки интерфейсных методов Node.js. Полная упаковка требует локальных зависимостей из раздела «Входы».

Исследованные текстовые спецификации колод находятся в `data/beta924/ai/references`. Исходный PDF стороннего обзора сохранён только локально в `BetaGwent/build-inputs/reference/local-research`; он не нужен для обычной сборки.

После изменения Board обновлять проверенные SHA в `tools/features091/prepare_ui091.py` только после проверки правки. Быстрый preflight проверит их до нативной компиляции. Пять копий Board, BOM/CRLF и ограничения размеров обязательны.

После изменений сохранений дополнительно запускать `python -X utf8 tools/ai/check_prepared_profiles198.py BetaGwent/build/МОЯ_ПАПКА BetaGwent/build/МОЯ_ПАПКА/profile-native-source-proof-complete.json`. Classic переносит добавленные поля/методы в `game/player/playerWitcher.ws`; проверка одного оставшегося `deckProfile.ws` не подтверждает доставку исправления. Проверки восстановления описаны в [DECK_RECOVERY_198_RU.md](DECK_RECOVERY_198_RU.md).
