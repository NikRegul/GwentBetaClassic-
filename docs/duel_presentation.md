## Результат

Игра записывает промежуточные снимки после розыгрыша карты, изменения силы/
брони, отправки в сброс, изменения погоды, паса и результата раунда. UI получает
всю последовательность и показывает её по очереди. Поэтому ход AI и несколько
погодных ударов больше не должны сливаться в один итоговый redraw.

Показаны перемещение карт из руки/выход AI, иллюстрация сыгранной особой карты,
рамки источника/цели, луч к цели, всплывающие изменения силы и брони, уход
погибшей карты в сброс. Есть плашки паса, начала раунда и результата/корон.
Показ новой руки/запроса цели появляется после последнего промежуточного кадра.

Кнопка «Пропустить анимацию» сразу показывает окончательное состояние.
«Заново», закрытие и Esc остаются доступными. Перезапуск обрывает старый
показ и начинает новую дуэль. Доски можно переключать во время показа.

## Граница игрового кода и UI

- Снимок CBetaGwentDuelVisualFrame содержит копии состояния карт, счётчиков,
  flags, weather, caption и cue. Получение снимка не вызывает правила/RNG.
- Все игровые действия рассчитываются прежним путём до воспроизведения.
  Очередь анимаций не является AbilityManager/ExecutionStack.
- На native Publish: PumpOpponent → TakeVisualFrames → beginVisualBatch →
  PublishFrame каждого снимка → текущий final snapshot.
- Flash staging не меняет отображаемые поля до получения целого batch.
  Каждый finishBoardState завершает один снимок, затем включается playback.
- Промежуточные snapshots не несут интерактивных request views. Рука AI,
  колода, сброс и execution stack не раскрываются через pushBoardCard.
  Иллюстрация особой карты раскрывается только после её розыгрыша.
- Все дальнейшие игровые intents блокируются в Script и UI на время показа.
  OnBetaGwentVisualDone принимает только актуальную final revision. Старая
  очередь не может разблокировать новую. Skip использует тот же final state.
- Restart допускается даже при fatal state и сбрасывает presentation guard.
  Close не зависит от animation ack.
- Не более128 промежуточных snapshots на batch; при переполнении записывается
  DUEL_VISUAL_TRUNCATED, оставшиеся visuals пропускаются, final state сохраняется.
- Длинные batches масштабируются к приблизительно8 секундам, minimum40ms/кадр.
  Обычные play480/power260/death320/weather380/pass550/round850/start650ms.
  Это время UI, не таймеры Beta.
