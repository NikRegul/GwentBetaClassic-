# Этап85: исправления контроллера, бочек и общий ИИ

Проверка пользователем этапа84 выявила три проблемы: у бочки нет рабочего
использования, редактор не реагирует на контроллер, бой пропускает часть
подтверждений и направлений. Предыдущую компиляцию не считаем приёмкой.

## Что изменено

Контроллер слушает события и на стадии захвата, и непосредственно на Stage.
Событие, направленное самому Stage, не вызывает его capture-listener;
раньше такой ввод попадал в старый ограниченный обработчик клавиатуры.
Обработанное событие останавливается, чтобы два слушателя не удваивали ход.
На краю списка добавлен переход на противоположный край той же строки/колонки.
Принимаются оси1000–1003 TW3 и значения Scaleform GamePad.
Штатный признак последнего устройства предотвращает отключение контроллера
из-за движения его виртуального указателя. Фокус, прозрачное место вставки,
обязательные варианты, редактор и просмотр используют прежние общие действия.

Бочка получает Consume непосредственно в окончательном Flash-объекте
инвентаря игрока, после исходного сериализатора. Торговля и тайник сохраняют
Sell/Transfer. У использования появился отдельный маркер в логе.
Дополнительно меню колод показывает «Открыть бочку · N»: оно расходует одну
уже купленную бочку из инвентаря, без повторной оплаты. Незавершённый выбор
возобновляется, не расходуя следующую бочку. Лимиты и сохранение вариантов
остаются прежними. Это доступно в отдельном меню колод, вне NPC-боя.

Общий ИИ получил первый следующий слой:

- При счёте1:0 необязательный второй раунд больше не разрешает любую погоню
  несколькими картами. Учитываются оставшаяся рука и преимущество по картам.
  При угрозе проигрыша матча расход ресурсов разрешён.
- Плохой раунд с малой рукой можно отдать, сохраняя карты для решающего.
  В решающем раунде ИИ пытается выиграть вместо прежнего немедленного принятия ничьей.
- Оценка возможного ответа использует наблюдаемые изменения счёта игрока
  и видимые возможности Казни/Игни/урона по ряду. Это вероятностная оценка,
  которая не гарантирует правильный пас против неизвестной комбинации.
- При размещении учитываются погода, заполненность и большие ряды,
  уязвимые для Игни. Стоимость создаваемых токенов учитывает их силу.
- Для ряда целевых способностей оцениваются добивание движков, последствия
  завещания, полезность лечения/сброса усиления/блокировки и подходящие цели усиления.
  Поиск карты для розыгрыша учитывает часть способности и призываемые копии.
- Шпионы с добором получают стратегическую ценность; этот будущий добор
  не считается уже полученными очками при погоне после паса. «Импера» получает
  приоритет подготовки, если в руке есть шпионы.
- Бран предпочитает сбрасывать Моркварга и налётчиков, затем дешёвые карты,
  сохраняя дорогие. Его непосредственный темп учитывает возвращающиеся отряды.

Это расширение общих эвристик, а не законченные стратегии всех архетипов.
Полный поиск последовательностей, особенно добор→ответ и взаимозависимые
призывы, ещё нужен. Расчёт не добавляет искусственную паузу25–30 секунд
и не использует игровой RNG для оценки вариантов.

## Одна короткая проверка

Сохранить игру, полностью закрыть REDkit и открыть проект снова: обновлены
WitcherScript и все три redswf, одной перезагрузки боя может быть недостаточно.

1. В обычном инвентаре вне торговли выбрать купленную бочку и использовать её.
   Выдать только одну; подтвердить одну редкую карту. Дополнительно открыть
   ещё одну через «Колода для игры в гвинт» → «Открыть бочку · N».
2. Контроллером открыть редактор, пройти вниз/вверх, добавить и удалить карту,
   выбрать лидера, сохранить колоду. A/× — подтверждение, B/○ — назад,
   LB/RB — страницы, Start/Y — переход к кнопкам меню.
3. В бою подтвердить муллиган, выбрать карту, выбрать прозрачное место
   в ряду и подтвердить. Затем подтвердить обязательную цель способности.
4. Сыграть обычный бой и проверить, что догоняющий ИИ не тратит несколько
   карт на заведомо невыгодный необязательный раунд. Остальные архетипы позже.

Лог агент читает сам. Маркеры: `CONTROLLER_INPUT`, `KEG_INVENTORY_ACTION`,
`KEG_INVENTORY_USE_REQUEST`, `KEG_CHOSEN`, `DUEL_AI_CHASE`, `DUEL_AI_PASS`.
Компиляция и проверки протокола не подтверждают работу реального контроллера.

Сборка установлена: Wcc85b успешно, три UI/44 связи проверены;
20 сценариев правил паса прошли. Опись входов: `BetaGwent/build/release85/input-manifest.json`.
Отчёт: [controller-and-ai85-result.json](evidence/controller-and-ai85-result.json).
